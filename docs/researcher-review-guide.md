# Researcher decision guide

## Optional model generation does not review

The disabled-by-default CLI adapter can generate an untrusted candidate from
explicitly confirmed public research; the ordinary chat handoff remains available.
Published prompt literals are source artifacts, never commands to execute.
Provider completion, usage metadata, JSON validity and exact quotation matching
are not human semantic approval. Explicit application creates Pending review
items, never an Accept/Modify/Exclude/Unsure event or completed human checklist.
Your existing corrections, exclusions and decision history remain separate.
An intervening review makes an unapplied frozen candidate stale: inspect the
protected result and re-prepare explicitly rather than rewriting its hashes.

## Staged extraction and independent comparison

The owner-approved initial stages are Ground (atomic claims and exact tool/product,
prompt, command/flag literals), Interpret (behavior definitions/occurrences) and
Relate (supported paths/nodes/edges and framework mappings). Grounded applied
Pending support may be used for derivation; dependent acceptance still requires
accepted support and a separate decision on each output. Existing proposal,
reported/attempted/inferred, provenance and reviewed-export rules remain in force.
Human modifications shown in frozen stage inputs are effective derivation context,
not edits to the original extraction.

Before any authorized Nx/s1ngularity regeneration, preserve the old extraction,
all retained revisions, run configuration and review overlays in a protected
baseline. Use a separate new candidate, retain identical source revisions, and
do not copy old decisions onto new IDs. A baseline is not semantic gold just
because it exists or is Pending. No regeneration, external transmission or
adoption is implied by installing this implementation.

An independent researcher must select a small frozen evaluation set of exact
retained spans covering positive/negative claims, complete literal prompts and
commands, tool identity/usage, actor/role, attempted versus observed behavior,
contradictions and unsupported relationships/mappings. Record the span/hash,
expected claim/literal/classification and allowed interpretation **before**
inspecting the new result. Preserve this sensitive set privately. For each stage,
record missed and unsupported items, literal/evidence differences and corrected
classification; record latency/cost only when actually measured, including unknown
values and provider/configuration differences. Synthetic tests and record counts
are mechanism evidence, not semantic-quality evidence.

Generate the comparison using the documented CLI. It accounts for every populated
review-unit category, including categories not generated by the initial stages.
ID-independent exact signatures identify conservative matches; same-type evidence
overlap suggests changed/split/merged groups, not an authoritative semantic match.
Inspect matched groups too for reference-summary limitations and false equivalence.
All added, omitted, split/merged or changed groups are major by default under
`campaign-major-mismatch/1`. Material evidence/literal integrity, identity/usage,
role/classification, behavior/boundary, relationship/mapping, contradiction and
coverage discrepancies require independent source adjudication; equal counts or
a similarity score cannot clear them. Whole retained revisions labeled context
are not asserted supporting passages.

Create a protected `campaign-comparison-adjudication/1` JSON with
`comparisonHash`, `reviewer`, `independent: true`, `selfAttested: true`,
`approveSelection: true`, `rubricVersion: "campaign-major-mismatch/1"` and
`decisions`. Each major group needs exactly one `{differenceId, outcome, rationale,
evidence}` entry. Outcome is `corrected-and-rechecked` or `accepted-evidence-backed-change`;
evidence entries contain exact `{revisionHash, start, end, quote}` copied from
retained comparison evidence and a nonblank source-backed rationale. A correction
to candidate output requires regenerating the comparison before adjudication.
Unresolved groups cannot be silently dismissed. Self-attestation is not
authenticated independence; a person must verify the reviewer and reasoning.

Only then explicitly select the new private working baseline. Keep the old store
and baseline inspectable. Selection does not establish complete extraction,
item acceptance, release eligibility or permission to update the public snapshot.
Changed compared content/annotations requires a current comparison and approval.
Publish only authorized non-sensitive aggregate evaluation/adjudication results,
with exact revisions and remaining limitations, on the originating PR. Independent
semantic, UX/accessibility and documentation-relevance review remain required.

## Public-baseline recovery and review checklist

Issue #91's human-authorized starting point is the existing public Pending Nx
projection, not an unavailable historical private store. The authorized review
scope includes tools, prompts/responses and behaviors with their supporting
claims. Use the [explicit recovery command](reference/cli.md#recover-an-authorized-public-pending-baseline)
to make a new private working copy from matching retained evidence. It is not a
recovered original extraction run and must not carry invented run provenance or
copied approvals. The existing public display remains read-only.

Apply this checklist separately to each publisher:

| Step | Evidence to preserve | Stop or defer when |
|---|---|---|
| Authorize and freeze | Operator authorization, exact baseline byte hash, typed snapshot digest, scope and source URLs | Permissions/scope are ambiguous, or the baseline has changed without approval |
| Collect and match | Protected source archive and retrieval result, parser/normalization versions, matching normalized hash/count, historical versus fetched raw hashes | Retrieval is denied/failed, normalized text differs, or a citation/quotation receipt does not verify |
| Restore Pending | Separate output store, byte-identical baseline copy, recovery receipt, unchanged core/artifact IDs and dependencies | Output already exists, content is missing, literal/response grounding fails, or filesystem protections fail |
| Review evidence | Each supporting claim's exact passage/revision and explicit human Accept/Modify/Exclude/Unsure decision | Evidence does not support the claim, a conflict is unresolved, or the reviewer is unsure; never accept in bulk |
| Review derived items | Separate tool identity/usage, exact prompt/response pairing/context and behavior/occurrence decisions after supporting claims | Support is not currently accepted, the literal/context is wrong, or dependency bindings change |
| Bound gold and release | Versioned included/excluded/deferred IDs with reasons, eligibility closure, source revisions, comparison/adjudication, export hashes and independent approvals | Evaluation/comparison, rights/privacy, independent research or publication approval is absent |

The current Nx draft has 97 claims, 14 behavior definitions, 12 tool occurrences
and four prompt occurrences (two literal variants, one attached response). These
are workload inventory counts, not accepted findings. Source-local categories,
scope proposals, path/node/edge and mapping records remain visible and need their
own explicit decisions if included. The case summary has no independently cited
support in this projection; leave it unaccepted. Existing reviewed exports may
include only minimal context-only case identity rather than an unreviewed summary.

Original model/prompt versions were omitted from public artifacts. Recovery marks
them unknown rather than inventing extraction metadata. Matching normalized
evidence can restore exact citations while fresh raw HTML has different hashes:
never write a new raw response beneath the old revision's raw hash or archive ID.
Retain the separate retrieval store and recovery receipt alongside the review store.
The ignored directory is neither an access-control mechanism nor a backup.

An already-published candidate cannot retroactively satisfy a pre-output evaluation
freeze. Arrange an independent, exposure-aware frozen set before any **new**
regeneration, and adjudicate the same-revision comparison separately from new-source
coverage. Recovery is not either of those activities. If no human-qualified gold
scope can be established, preserve the useful review history, report the remaining
gates, keep the draft Pending and do not publish or close #91 as accepted.

This checklist and the interface still require independent documentation relevance,
research, privacy, keyboard/narrow-screen and accessibility review.

## Interface clarification (decision rules unchanged)

Current **Human-reviewed · Excluded** means a completed exclusion decision, not
acceptance. Stale decisions are not current review. After explicit supporting-item
review, the original workload/category/group/source/filter resumes, even after
reload. Identical passages at the same revision/code-point span display once with
all passage/direct-support attributions and supporting-record links retained;
different spans or revisions are not merged. A corrected tool display identity
appears consistently on private cards/library while its extracted literal remains
visible; a correction never automatically merges products. These presentation
clarifications do not change either named guide's acceptance checks.

## Current guide: researcher-review/4

Version **researcher-review/4** adds the **Telemetry scope** queue and nested
**Prompts & responses** review. It preserves historical v1/v2/v3 guide versions
and bindings, not their acceptance on changed content. Scope confirmation says
the source-local behavior fits a collection family; it establishes neither
available logs nor events/detection coverage. Correct, exclude or defer any
unsupported proposal; acceptance still depends on separately accepted claims.

A response belongs to its exact prompt occurrence, never a new prompt card or
all occurrences of a shared prompt. Inspect the full raw response and context
receipts as well as supporting claims: a claim may support only an opening
refusal. JSON-string tokens retain raw offsets/hashes while displaying decoded
text. Unknown role/model stay unknown. Distinguish researcher-controlled testing,
reported compromised-host evidence, unspecified-environment log review,
illustration and unknown; neither attacker testing pretexts nor a separate
malware experiment establish the environment of an AI exchange.

The prompt confirmation is: “The prompt and any attached responses, pairing and
observation contexts are source-supported; unknown is not independent testing
or compromised-host proof.” Saving outcome/context corrections does not
accept them. A correction cannot reassign response identity, source support or
claim dependencies; use a separately grounded Pending artifact for changed
evidence. Edited support, response content or provenance invalidates prior
acceptance. Public preview cannot save decisions; reviewed public annotation
exports still omit private prompt/response/context content.

Reader display is not review completeness: Prompt library initially shows only
published pairs. Choose **All prompts**, follow a direct occurrence link, or use
the full Prompts & responses queue to inspect prompt-only records. Collapsed
Technical provenance retains full pairing/observation metadata and receipts;
the shorter visible summary does not replace that review. Campaign/blog scope
tags open Security telemetry, where supporting claims and the private
**Review telemetry scope** action remain available. Claim-side Related research
links use the same explicit support projection, not independently inferred evidence.

## Historical guide: researcher-review/3

Version **researcher-review/3** adds **Campaign categories** to the priority
workload and distinguishes **Rule-derived** labels / **Deterministic rule**
content from LLM-derived and human-authored contributions. It retains the v2
evidence, fidelity, scope and type checks and explicit personal attestation.
Historical v1/v2 events remain bound to their original version; no event is
upgraded, copied or accepted by this change.

Campaign categories can overlap: **Victim-side agent abuse**, **Attacker-side AI
use**, **AI review targeting**, and **Developer-targeted social engineering**.
They are local research/navigation labels, not new MITRE technique IDs. Review
each source-local proposal and its supporting claim separately. Rules inspect
bounded English sentences in source-linked claim descriptions, not whole-article
keyword co-occurrence or a semantic model. Reported/attempted/refused agent use is
not universal success; recommendations, ambiguous roles and missing matches must
not become positive facts or a "no AI" finding.

Use the category dropdown to correct a high-level value, or Exclude/Unsure when
unsupported. A saved correction retains the original proposal and needs separate
acceptance. Changing support invalidates dependent decisions. The rule version
and ID remain inspectable; **Rule-derived** describes label production, not
independent evidence. Public Nx remains read-only: absent private article text
cannot be bypassed by accepting a category in the preview.

## Historical guide: researcher-review/2

Version **researcher-review/2** retains the exact evidence, fidelity, scope and
type-specific checks printed below, but replaces four separate check inputs with
one explicit human attestation. Historical v1 decisions and the original v1 guide
below remain unchanged; a newer guide never upgrades an older decision.

Set your reviewer identifier and self-attestation once per tab/session (editable
at the top of Review). This is not authenticated identity. Session storage retains
that identifier through reload, not in the navigation bookmark; each saved
decision separately records identity, time, guide, item/evidence/support bindings.
Coordinate one active human reviewer locally.

Start with AI/coding tools, behaviors/occurrences or prompt literals, grouped by
artifact category; blog grouping covers the same distinct records. Claims remain
supporting evidence in the advanced/evidence queue, never deleted or bulk rejected.
An actionable priority item deterministically has a supported category, an exact
retained passage and no missing, cyclic, unresolved or mismatching required support.
Pending supporting claims are visible in a short, explicit support-review step:
review and accept each separately, then return to the candidate. No hidden support
is approved by accepting a derived item. Exceptions remain visible in their queue.

Read the candidate, literal/citation, usage/context and compact supporting claims.
**Accept item — I confirm** is one explicit human action confirming:

> I personally checked evidence, fidelity and scope. [Applicable category/type
> rule.] Reported is not confirmed; attempted is not successful.

For tools the rule is “The tool identity, extracted literal and usage are supported.”
For prompts it is “The prompt literal is exact and its usage/context are supported.”
Other types use their exact type-specific check below. This action records each
applicable check as personally confirmed; no LLM suggestion completes a check.
The collapsed guide lists the checks; documented non-applicability is contextual,
requires a reason and cannot waive evidence or dependencies.

Reject offers unsupported, inaccurate, duplicate, outside scope, misattributed
or insufficient evidence; the choice itself supplies canonical rationale, optional
prose adds detail. Other requires prose. Unsure also requires a reason. Navigation
alone records nothing. Original candidates, LLM contributions and history remain.

Modify reveals prefilled friendly fields: tool identity/usage; prompt literal,
context/usage; behavior name/description/boundary. Save changes is **not** acceptance:
inspect and explicitly accept afterward. A changed literal absent from its exact
passage is flagged and blocked; exclude/regenerate instead of inventing grounding.
After a decision the next actionable item is offered with confirmation and a
previous-item/history link. Supporting-item review returns to its candidate.

Priority progress shows separate per-type denominators and discloses hidden
evidence, exceptions and deferred advanced records. N/A records are excluded from
label denominators, not counted as labeled. Extraction unions retained canonical
code-point ranges across runs and chunk-policy versions without double counting
overlap. Historical partial runs without positions are disclosed separately and
not counted in the canonical coverage numerator. This reporting change does not
alter the versioned acceptance checklist or historical decisions.

Reviewed exports include minimal, explicitly **context-only** case identity rows
when an accepted item needs its case but the summary is unreviewed. These rows have
no summary and no acceptance. Case summaries never become claim prerequisites.
Private views display effective edits/review state while original proposals remain
inspectable in Review. The published preview is unchanged.

Advanced mappings, timelines, summaries, path structures, telemetry/detection and
instrumentation retain generic review/withholding but polished fast workflow and
semantic acceptance are deferred. They remain Pending/withheld unless explicitly
accepted with their own prerequisites. Human review is not operational validation.
Independent researcher, documentation and keyboard/narrow-screen/accessibility
review remain required before merge.

## One item, one human decision

Identity is explicitly self-attested, not authenticated. Coordinate locally so one
human reviews at a time. LLMs propose content and evidence; they cannot check boxes,
accept records or establish human authorship. Read the exact revision and available
context, inspect uncertainty/conflicts and follow supporting-record links.

Accept applies only to the selected revision. Accepted supporting claims and other
required artifacts are prerequisites, not automatic approval of a derived item.
Modify makes a human-edited revision; inspect it again and explicitly Accept.
Simple content fields, annotation context labels and researcher tags can be edited.
Structural/precision/support corrections should be excluded and regenerated using
the existing extraction workflow, not patched into a graph or inferred chronology.

Exclude requires a reason: unsupported, inaccurate, duplicate, outside scope,
misattributed or insufficient evidence. Retain the original candidate, attribution,
support, extraction metadata and history; record replacement links if known.
Exclusion means “not included here”, not “false” or a negative training label.
Unsure requires a reason and is appropriate for ambiguous attribution, incomplete
evidence or unknown usage. Stop rather than guess. Next item/navigation records no
decision. Revisit excluded/unsure items through their filters.

Content origin, label authorship and human review are independent. An accepted
LLM-derived record stays LLM-derived. Human-edited indicates an editor, not a new
original author. Human-reviewed indicates current acceptance, not independent
truth or validated deployment. Correct provenance is a separate audited action:
give the reason and available evidence, including justified human-to-LLM
corrections. Prior attribution remains visible; affected approvals need re-review.

## Labels and required fields

Use existing labels plus researcher tags, not a new taxonomy. Completeness means
required fields are populated by anyone; it does not mean correctness or approval.
Missing/incomplete/complete labels are independent of authorship and review.

| Artifact | Required label fields / rule |
|---|---|
| Claim | evidenceStatus; proposed description and exact passage or explicit supported inference |
| Case summary | No label applies; summary and supporting claims |
| Category | dimension and value (existing controlled values or researcher tag) |
| Timeline | dateType and date.precision; retain supported value/range/null reason |
| Behavior | boundary; name, description and supporting claims |
| Behavior occurrence | No label applies; distinct source-local claim support |
| Path | scope; independently reviewed nodes and relationships |
| Node | evidenceStatus; action and supporting behavior/claims |
| Edge | relation and basis; its own supporting evidence, not just endpoints |
| Framework mapping | framework, version, techniqueId, mappingStatus; pinned definition, rationale, limits |
| Telemetry | category, eventType, availability; honest proposed collection and limitations |
| Detection | validation; hypothesis, test plan and support (review does not test it) |
| Instrumentation | sampleOrigin, stability; action and inert synthetic sample |
| Every annotation | type and evidenceStatus; value and source revision/support |
| Prompt/tool annotation | context.artifactKind and context.artifactUsage |
| IOC annotation | context.indicatorKind |
| Role annotation | context.roles |
| Behavior annotation | context.behavior |
| Data-source annotation | context.collection |
| Mapping annotation | context.mapping |
| Detection-reference annotation | context.detection |
| Talk tag | No additional context label applies |

“Source-reported observation” records a report, not independent confirmation.
“Attempted behavior” does not establish execution or success. “Researcher inference”
retains rationale/support and is not a literal source assertion. “Confirmed” may be
used in prose only with evidence of what, by whom and within what scope was
confirmed. Demonstrations/vendor examples and potential consequences remain distinct
from incident observations. Tool/prompt usage labels are targeted, attempted-abuse,
reported-abuse, vendor-example, general-mention or unclear.

Example: include a literal prompt with its exact spacing, source and vendor-example
usage when it is a vendor demonstration; do not call it observed attacker use.
Include an attempted action as attempted, not successful. Exclude an unsupported
sequence between two otherwise supported nodes. Defer an ambiguous executable
identity rather than guessing a product. A catalog technique definition may be
reference metadata, but its mapping needs its own review.

## Mandatory personal checklist

Every Accept records all three common checks and the applicable type check.
LLM suggestions never complete them. A genuinely non-applicable check requires
an explicit explanation; a reason does not supply missing required evidence.

- Supported by the cited evidence; uncertainty and conflicts are explicit.
- Faithful to the source; reported, attempted, inferred and confirmed are not interchangeable.
- Correct campaign, source occurrence, actor/role and scope.

### Type-specific checks (exact UI text)

- Claims: The atomic claim and its evidence classification are supported.
- Cases: The summary adds nothing beyond its independently accepted supporting claims.
- Categories: The existing category/tag value and its scope are supported.
- Timelines: The date type and precision are supported, not invented.
- Behaviors: The behavior definition adds no unsupported action or trust boundary.
- Occurrences: This distinct behavior occurrence has its own source-local support.
- Paths: The path scope is supported; ordering is not inferred from layout.
- Nodes: The node action and linked behaviors have independent support.
- Edges: This relationship has its own evidence; accepted endpoints do not approve it.
- Mappings: The mapping fits the pinned definition; membership alone is not evidence.
- Telemetry: Collection is a proposal unless separately evidenced; availability is honest.
- Detections: Human review approves a proposal, not operational validation or deployment.
- Instrumentation: Instrumentation remains a proposal; synthetic samples are not incident evidence.
- Annotations: Identity, role and usage are supported; prompt literals and use context are exact.

## Eligibility and limits

Source/content/provenance/support changes invalidate affected decisions. Exclusions
block dependents. Missing support and cyclic prerequisites stay blocked; follow the
links, exclude or regenerate instead of accepting around the blocker. Other records
are never automatically accepted. Case summaries do not become claim prerequisites.

Reviewed profiles contain only accepted reviewable records and eligible dependencies;
pending optional enrichment cannot qualify. Public profiles strip article bodies and
passage text and conservatively withhold annotation content. Private campaign/talk
exports remain research drafts and can contain private text. No action publishes.

Campaign progress deduplicates stable review units. Source counts may overlap and
must not be summed. Extraction measures eligible retained canonical code points, not all
incident facts. Unavailable/unprocessed sources remain separate. Accept and Exclude
complete current review; Unsure and changed/stale decisions do not. Ready means
current release eligibility, not quality. Zero denominators are N/A, never 100%.

Independent researcher, semantic, UX, keyboard/narrow-screen accessibility and
documentation-relevance review remain required; automated tests are not that review.
